# Code Review — snippet.py

## 🚨 Blockers
- **SQL injection**: `LoginUser` builds a query with an f‑string (`... WHERE name = '{Username}' ...`). Critical (Bandit B608, OWASP A03).  
- **Weak crypto**: MD5 used for password hashing (`hashlib.md5`). High (Bandit B303, OWASP A02).  
- **Command injection**: `runCmd` passes raw `cmd` to `os.system`. Critical (Bandit B602, OWASP A03).  
- **Insecure deserialization**: `loadProfile` unpickles arbitrary files with `pickle.load`. Critical (Bandit B403, OWASP A08).  

## ⚠️ Should Fix
- **Mutable default argument**: `Password=[]` in `LoginUser` shares state across calls.  
- **Incorrect comparisons**: `data[0] is "admin"` and other `is` string checks; should use `==`.  
- **Inefficient loops**: `for i in range(len(data))` with string concatenation; replace with direct iteration and `"".join`.  
- **Type checks with `type()`**: replace with `isinstance()`.  

## 💡 Nice to Have
- Add module‑level and per‑function docstrings (Google style) describing args, returns, and raised exceptions.  
- Rename parameters to follow Python conventions (`username`, `password`).  
- Use parameterized queries (e.g., `cursor.execute(sql, (username,))`).  

## ✅ Good
- Use of context manager for file handling where present.  
- Clear separation of concerns across functions.  

## Verdict
**REQUEST CHANGES** — Critical security flaws (SQL/command injection, unsafe deserialization, weak hashing) must be fixed before merging.
