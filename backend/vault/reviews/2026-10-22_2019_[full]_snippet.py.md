# Code Review — snippet.py

## 🚨 Blockers
- **runCmd** uses `os.system("echo " + cmd)`. User‑controlled input is concatenated → command injection (Bandit B602, OWASP A03).  
- **loadProfile** loads data with `pickle.load`. Insecure deserialization enables remote code execution (Bandit B506, OWASP A08).  
- **LoginUser** builds an SQL string via f‑string and hashes passwords with MD5 → SQL injection and weak credential storage (Bandit B608, B303; OWASP A03, A02).

## ⚠️ Should Fix
- Replace mutable default `Password=[]` with `Password: Optional[str] = None`.  
- Use parameterized queries (`cursor.execute(sql, params)`) and a strong password hash (e.g., bcrypt).  
- Remove bare `except:`; catch specific exceptions and log them.  
- Switch `os.system` to `subprocess.run([...], check=True)` without a shell.  
- Swap `pickle.load` for `pickle.safe_load` or a safer format (JSON, pydantic).  
- Add docstrings to `LoginUser`, `loadProfile`, `runCmd`, and `Process` describing params, returns, and raised errors.  

## 💡 Nice to Have
- Add type hints to all public functions.  
- Use `logger.info`/`warning` instead of silent failures.  
- Validate file paths in `loadProfile` to prevent path traversal.  

## ✅ Good
- Context manager usage elsewhere is correct.  
- Code layout is clean and follows project formatting conventions.  

## Verdict  
**REQUEST CHANGES** – critical security flaws (command injection, insecure deserialization, SQL injection) must be fixed before merge.
